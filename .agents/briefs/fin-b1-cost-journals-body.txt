GOAL
Cost-item edits, cost adjustments and cost-item deletes must keep the general ledger equal to the cost sub-ledger. Today none of them posts a journal entry. The audit found the GL 20,000 above the sub-ledger after one edit (zakaria-farid/.agents/audits/SIM-2026-10-07-admin-lifecycle.md, B1 and B7).

BINDING RULES (PROJECT_SPEC.md, "Partner payouts and final pricing", [user-confirmed 2026-10-07])
- Edit: when the amount changes, post ONE entry for the difference only, construction WIP (the item's category account) against payables 201000. The original entry stays. Edits that do not change the amount post nothing.
- Adjustment: post ONE entry for the adjustment amount only. A supplement posts Dr category account / Cr 201000. A refund posts Dr 201000 / Cr category account.
- Delete (24h window): post ONE entry reversing the item, Dr 201000 / Cr category account, for the item's current net effective cost. Block the delete if paid amount > 0.

REQUIRED
R1. In propertyCostEngine.ts add and export ONE pure function:
    buildCostCorrectionJournalLines(params: { category: PropertyCostCategory; delta: string | number; memo: string }): ConstructionExpenseJournalLine[]
    - delta > 0: [Dr getPropertyCostAccountCode(category) delta, Cr '201000' delta].
    - delta < 0: [Dr '201000' |delta|, Cr category account |delta|].
    - delta == 0: [].
    - Amounts are strings with toFixed(2) via D(). No float math.
    Use this one function for edit, adjustment and delete. Do not add a second builder.
R2. Edit (handleUpdatePropertyCostItem):
    - Look up the original item in state.
    - delta = D(new total_cost_egp).minus(original total_cost_egp).
    - Reject the save with a clear Arabic/English error when the new total is below the item's paid amount (paid_amount_egp).
    - If delta != 0: build the entry, then save the row with updatePropertyCostItem, then persist the entry with persistJournalEntryGuarded.
    - If persisting the journal fails: restore the row to the original item with updatePropertyCostItem, then rethrow.
    - entry_number: `JE-WIP-EDIT-${item_id.slice(0,8).toUpperCase()}-${Date.now().toString(36).toUpperCase()}`.
    - source_module 'WIP_ALLOCATION', source_entity_id property_id.
    - The period is today's period, from the same helper other handlers use. A closed period blocks the save.
R3. Adjustment (handleAddCostAdjustment):
    - The new adjustment is the one present in updatedItem.adjustments and absent from the state item. Match by its id field; read the type for the exact name.
    - delta = +amount for a supplement and -amount for a refund. Read the adjustment type field and its exact enum values in types.ts.
    - Same order and rollback as R2.
    - entry_number `JE-WIP-ADJ-${adjustment id .slice(0,8).toUpperCase()}`.
R4. Delete (handleDeletePropertyCostItem):
    - If D(paid_amount_egp).gt(0), throw a clear Arabic/English error and delete nothing.
    - Otherwise persist the reversal entry first, with delta = -net effective cost from calculateCostItemEffectiveTotals, then delete the row.
    - If the delete fails after the journal was posted, post the opposite correction (delta = +net) and rethrow.
    - entry_number `JE-WIP-DEL-${item_id.slice(0,8).toUpperCase()}`.
R5. Remove the silent fallbacks:
    - The catch blocks in handleUpdatePropertyCostItem and handleDeletePropertyCostItem currently change local state as if the save succeeded. Replace them with toast.error (message + description) and rethrow, matching handleAddCostAdjustment's catch.
    - Local state changes only after success. Also add the posted journal entry to local journal state the way other handlers do after persistJournalEntryGuarded (read how, for example, at ~2127).
R6. EditPropertyCostModal: keep the layout. Make sure a thrown error leaves the modal open and is shown (it may already be so; verify). No visual changes.
