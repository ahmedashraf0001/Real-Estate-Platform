TASK fin-c2b-partner-id-race (FINANCIAL_CORE follow-up to fin-c2-partner-id-lines, commit 4a021ff)

PROBLEM (from the independent audit of c2; the race predates c2)
zakaria-farid/src/lib/erp/supabaseService.ts persistPartnerProfile (~2040-2099): when no UUID is known it looks the name up, else generates a UUID, then calls .upsert(row, { onConflict: 'name' }). Two concurrent first-time saves for the same name both generate UUIDs; the second upsert REPLACES partner_id on the existing row, so the first journal's partner_id points at a UUID that no longer exists. The same overwrite happens whenever a caller passes a stale UUID that differs from the stored row's partner_id.

REQUIRED
R1. A profile row's partner_id must never change once stored. Insert only when the name is new (insert with conflict-do-nothing, e.g. upsert(row, { onConflict: 'name', ignoreDuplicates: true })); update the other fields (phone, email, national_id, role, updated_at) by name WITHOUT partner_id; then read back partner_id by name and return the STORED UUID. Check that the ERPWorkstationContext callers (~3395, ~3540, ~3557, ~3781, ~3856) use the returned value, not the one they sent.
R2. Keep current error behaviour: schema-cache errors return undefined; other errors throw; lookup errors still block writes.
R3. Smallest diff. No migration. Verify in zakaria-farid/supabase/migrations that erp_partner_profiles.name has a unique constraint and report the file:line.
