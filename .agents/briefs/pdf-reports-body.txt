DECISIONS (user-confirmed 2026-10-08)
- Arabic only, RTL. Readers: admin, clients, partners (as evidence).
- Summary tables + journal-entry reference numbers per row (not full journal lines).
- National id and phone masked as in mockup (first 4 + last 3 digits for id; first 4 + last 3 for phone).

OUTPUT METHOD
HTML-based: build a standalone, self-contained A4 HTML document (inline CSS, ThmanyahSans via the app's /fonts/*.woff2 absolute URLs, @page size A4 margin 0) and print it from a hidden iframe (or a new window) so the browser's "Save as PDF" produces vector text with correct Arabic shaping. document.title = statement number + name so the saved file is named sensibly. No rasterizing libraries (no html2canvas/jsPDF/html2pdf). No new dependencies. Long tables must paginate cleanly: thead repeats per page, rows never split, footer shows "صفحة X من Y" via CSS counters where the browser supports it (otherwise statement number only — say which).

ARCHITECTURE
- One module, e.g. zakaria-farid/src/lib/erp/statements/: pure data builders (buildPropertyStatement, buildClientStatement, buildPartnerStatement) returning typed view models, plus one renderer (statementHtml.ts) producing the HTML string with proper escaping of every user-supplied string. A small print helper opens/prints it.
- Builders MUST reuse existing engines, never re-derive money rules: net cost = base + supplements − refunds (existing cost/audit helpers, e.g. calculatePropertyAuditMetrics), partner available-to-pay = collections share − payouts − unpaid commitments (partnersEngine / erp-partner-payout-pricing skill rules, read zakaria-farid/.claude/skills/erp-partner-payout-pricing/SKILL.md first), installment status/overdue days from the existing installments logic. Use the Decimal helper D for sums. Read PROJECT_SPEC.md "Partner payouts and final pricing" — [user-confirmed] lines bind.
- Ledger match section (property statement): show only rows the system can truly compute (GL vs sub-ledger for that property). If a per-property GL figure is not derivable, omit that row; never show a fake "مطابق". If it does not match, show "غير مطابق" with the difference in red.
- Statement number: deterministic, no migration: ST-P / ST-C / ST-R + issue timestamp (YYYYMMDD-HHmm) + first 8 chars of the entity id.
- Missing data: hide the field/row (e.g. no national id -> omit). Empty sections show one muted line, not a blank table.
